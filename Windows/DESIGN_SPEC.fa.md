# طرح رابط ویندوز V2rayWatch — نسخه 0.2

این سند مبنای پیاده‌سازی رابط اختصاصی Windows است. تصویر مفهومی داشبورد باید در کنار این سند به‌عنوان مرجع بصری استفاده شود؛ اعداد و سرورهای داخل تصویر صرفاً نمونه‌اند و دادهٔ واقعی نیستند.

## جهت طراحی
- هویت بصری مستقل V2rayWatch؛ زمینهٔ سرمه‌ای تیره، پنل‌های لایه‌ای، تأکید فیروزه‌ای/آبی و وضعیت‌های سبز/قرمز.
- طراحی دسکتاپ برای Windows 10 و 11، با مقیاس‌پذیری در عرض‌های 1100 تا 1600 پیکسل.
- دو زبان فارسی و انگلیسی؛ RTL واقعی در فارسی و LTR در انگلیسی. انتخاب زبان مستقل از زبان سیستم و ذخیره‌شده در تنظیمات.
- فونت فارسی خوانا (Vazirmatn یا Segoe UI fallback) و Segoe UI برای انگلیسی.
- رعایت کنتراست، فوکوس صفحه‌کلید، tooltip و حالت‌های hover/disabled.

## ساختار اصلی
1. نوار عنوان: نشان V2rayWatch، انتخاب FA/EN، کنترل‌های پنجره.
2. نوار ناوبری: داشبورد، سرورها، اشتراک‌ها، مسیریابی، گزارش‌ها، تنظیمات.
3. داشبورد:
   - کارت اتصال: وضعیت قطع/درحال اتصال/متصل/خطا، سرور فعال، پروتکل/هسته، تأخیر، دکمه اتصال.
   - کارت‌های سرعت دانلود و آپلود، مدت اتصال و حجم مصرفی.
   - نمودار زنده ترافیک با محور زمان و راهنمای دانلود/آپلود.
   - فهرست سرورها با نام، کشور، تأخیر، وضعیت و انتخاب سرور.
   - کنترل‌های System Proxy و TUN با توضیح سطح دسترسی Administrator.
4. نوار وضعیت: هسته فعال، وضعیت سرویس، نسخه برنامه و آخرین خطا/آمادگی اتصال.

## صفحات و رفتارها
- سرورها: افزودن دستی URI، ورود از Clipboard/QR/فایل، ویرایش، حذف، گروه‌بندی، تست تأخیر، اتصال و مرتب‌سازی.
- اشتراک‌ها: افزودن URL، به‌روزرسانی دستی/زمان‌بندی‌شده، نمایش زمان آخرین به‌روزرسانی و تعداد پروفایل‌ها؛ مخفی‌سازی امن URL در UI.
- مسیریابی: انتخاب حالت Rule/Global/Direct و مدیریت قواعد؛ نمایش هشدار پیش از تغییرات مؤثر بر کل سیستم.
- گزارش‌ها: رویدادهای اتصال، خطاهای هسته، تغییر پروکسی و خروجی قابل کپی؛ عدم ثبت محتوای حساس کانفیگ.
- تنظیمات: زبان، اجرا هنگام ورود، رفتار Tray، هسته پیش‌فرض، DNS، به‌روزرسانی و حریم خصوصی.

## اصول اتصال به موتور
- این طراحی لایهٔ UI است و نباید موتور پروکسی را بازنویسی کند. در گام اول از APIها و سرویس‌های موجود v2rayN استفاده شود.
- وضعیت اتصال، سرعت و تأخیر باید از سرویس واقعی خوانده شوند؛ دادهٔ نمایشی/ساختگی فقط در حالت Design Preview مجاز است.
- دکمه‌ها و Toggleها باید به عملیات واقعی متصل باشند و در زمان عملیات حالت loading/disabled نشان دهند.
- خطای دسترسی TUN، نبودن Core، نامعتبر بودن URI و قطع اتصال باید پیام فارسی/انگلیسی روشن داشته باشند.
- عملیات خطرناک مانند پاک‌کردن همه پروفایل‌ها یا تغییر پراکسی سیستم نیازمند تأیید هستند.

## ترتیب پیاده‌سازی
1. ساخت Shell و Design Tokens، نوار عنوان و ناوبری دوزبانه.
2. پیاده‌سازی داشبورد و اتصال آن به وضعیت واقعی Core.
3. صفحات سرورها و اشتراک‌ها و جریان‌های Import/QR.
4. تنظیمات System Proxy/TUN، مسیریابی و گزارش‌ها.
5. تست خودکار UI و build؛ سپس تست دستی روی Windows 10/11.

## معیار پذیرش
- هیچ عدد، سرعت، سرور یا وضعیت اتصال ساختگی در نسخه Release نمایش داده نشود.
- تغییر زبان بدون ری‌استارت غیرضروری انجام شود و RTL/LTR همهٔ کنترل‌ها درست باشد.
- تمام کنترل‌های قابل کلیک عملکرد واقعی و بازخورد خطا/موفقیت داشته باشند.
- رابط در اندازه‌های مختلف پنجره و مقیاس 100% تا 150% قابل استفاده بماند.
- امکانات موتور فعلی (Xray، sing-box، System Proxy و TUN) در جریان طراحی حفظ شوند.
